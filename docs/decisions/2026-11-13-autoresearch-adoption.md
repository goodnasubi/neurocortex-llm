## 所有者の決定（大枠）

Andrej Karpathy の autoresearch の思想を取り込む。原典の核は、固定層（データ準備・評価。エージェントは変更しない）／可変層（エージェントが編集してよいのは1ファイルだけ）／指示層（人間が編集する `program.md`）／固定時間予算／単一指標による keep・revert の機械判定、である。

ただし原典の形（指標を見て直すループ）のままでは、本プロジェクトの規律と衝突する。評価 seed の一発計測（事前登録した seed で一度だけ計測する）が真正性の要であり、指標を見て直すループを評価側に回すと 44.4 撤回の再発になる。また仮説と判定基準は事前登録し、結果を見て変えない。そこで二層ループに読み替える。

- **内側ループ（新設、autoresearch 式）**: 対象は開発・パイロット専用 seed のみで、評価 seed には一切触れない。固定層はデータ分割・トークン化・評価集合・評価スクリプト・真正性チェック（git クリーン確認、結果 JSON のスキーマ・有限性・ハッシュ照合）。可変層は1ステップにつき1つの実験ファイル（または1モジュール）に限定し、差分をレビュー可能に保つ。実験予算は全試行で同一に保つ（単位は下の小判断1）。主指標はステップごとに事前に1つだけ固定し、最小改善幅を超えたら keep、届かなければ revert を機械的に判定する。全試行（失敗含む）を実験ログに残す。ステップごとに `program.md` 相当の指示書を置く。
- **外側ループ（従来どおり、変更なし）**: ステップ設計 → 仮説の事前登録 → 大きな判断は typesafe-ai → 評価 seed で一発計測 → docs へ記録。内側ループの結果は設計の候補を絞る材料としてだけ使い、評価の結論には使わない。内側で何回試行したか（試行回数）も結果報告に明記し、多重比較の見かけを作らない。

**適用先（案A を所有者が選択）**: 次ステップ **44.17 の設計に組み込む**。44.17 のパイロット段を内側ループで回し、本実行は従来どおりとする。44.16 は事前登録済みで実行途中のため、途中のステップには混ぜない。案B（44.16 の運用パイロットで試す）・案C（文書化のみ）は不採用。44.17 の話題自体は 44.16 の完了後に選定する（44.16 の範囲外項目や結果が材料）。

metric_location: design_ref（confidence 0.98。design_ref 0.99、program_only 0.01、both_full 0.0）

いずれも近接なし。

1. **実験予算の単位はコーパス割合で固定する**。Colab は GPU 種別が保証されず L4/T4 で速度差が大きいため、壁時計固定では学習量が試行ごとに変わり、比較可能性と再現性が落ちる。割合固定なら 44.16 パイロット（1/32・1/8）の前例とも揃う。壁時計は予算ではなく、異常検知の目安としてログに残すに留める。
2. **主指標と最小改善幅はステップ設計文書（事前登録）で固定し、`program.md` は参照のみとする**（keep/revert の運用手順だけを持つ）。事前登録を唯一の正本とし、指示書の編集で指標がすり替わる事故を防ぐ。二重管理（両方に全文を書く）は版ずれのリスクがあるため採らない。

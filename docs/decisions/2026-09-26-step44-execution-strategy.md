**メリット**: 実験がすべて完了してから設計修正できる

- **並行して** Jetson で ステップ44.3（段階的統合）を実装・検証
- 実験結果に基づき、ステップ44.3 設計を修正

**メリット**: 実装知見を蓄積、設計のリスク低減、ステップ44 完了速度向上  
**デメリット**: 実験結果が出た後の設計修正コストあり

## 評価軸

### 軸1: 研究新規性（加重: 40%）

**問**: 脳型LLMの「実装実証」と「性能検証」のうち、どちらが新規性を生むか？

**分析**:
- **選択肢A**: 性能検証に注力 → 既知の仮説を実証するのみ
- **選択肢B**: 実装知見を段階的に蓄積 → 海馬→基底核→小脳の統合メカニズム探索が新規性をもたらす

**評価**: **選択肢B が優位（2:1）**  
理由: 「実装→小規模検証→修正」のサイクルで、実装上の複合効果（モジュール間相互作用）を定量化できる領域が新規

---

### 軸2: 神経生物学的妥当性（加重: 40%）

**問**: 海馬・基底核の統合検証が優先か、段階実装が優先か？

**AGENTS.md の理念**: 「神経生物学的妥当性 > 性能最適化」

**分析**:
- **選択肢A**: 性能検証先行 → 妥当性確認は後付け
- **選択肢B**: 各モジュールの計算論的役割を段階的に検証 → 妥当性を実装と同時に確立

**評価**: **選択肢B が優位（2.5:1）**  
理由: 「各脳構造の計算理論が実際に機能するか」を段階検証することで、妥当性が確立される。性能改善より妥当性確立が優先。

---

### 軸3: 実行効率（加重: 20%）

**問**: Colab 実験とJetson 作業の並行度、リスク・修正コスト は？

**分析**:
- **選択肢A**: 単純直線的、リスク低い、でも時間が長い（72h + α）
- **選択肢B**: 並行実行で総実行時間短縮、モジュール設計は独立しているのでリスク軽微

**評価**: **選択肢B が優位（1.5:1）**  
理由: Jetson でのステップ44.3 実装は CPU でも可能（軽量・検証用）。Colab 実験に依存しない進捗が可能。

## リスク評価

### リスク1: Jetson 実装が Colab 結果と矛盾した場合

**対応**: 
- ステップ44.3 で実装した Phase A/B/C の設計は、Jetson 小規模データでの検証結果
- Colab 実験結果（実データ）と異なる可能性がある
- 対応: Colab 結果に基づき、ステップ44.3 の loss weight / モジュール構成を修正し、再実装

**対応コスト**: 中程度（モジュール構造は独立しているため、設計修正は局所的）

### リスク2: Colab 実験が失敗・タイムアウトした場合

**対応**:
- Colab は 90 分無操作で切断。セッション保護機構が必要
- 中間 checkpoint が Google Drive に自動保存される
- 対応: クラッシュ時はチェックポイントから再開

**対応コスト**: 低（checkpoint から再開可能）
